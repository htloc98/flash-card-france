# Next.js and Cloudflare D1 Implementation Plan

**Goal:** Replace local/Supabase persistence with authenticated cloud storage while preserving the vocabulary study and import workflows.

**Architecture:** Next.js App Router on Vercel, Google OAuth through NextAuth/Auth.js with signed JWT sessions, and a server-only D1 REST client. Access is closed by default through an email allowlist. Each user owns their vocabulary, categories, and settings. Device speech preferences remain local.

**Tech Stack:** JavaScript, React, Next.js, NextAuth, Cloudflare D1 SQLite, Node test runner.

## Accepted Design

- Google must report a verified email; ALLOWED_EMAILS must explicitly allow the user. An empty list denies access.
- Store Google subject as the stable external identity, never use a browser-supplied owner ID.
- D1 tables: users, vocabularies, categories, vocabulary_categories, user_settings, seed_imports. Composite foreign keys prevent cross-owner category links.
- Preserve the five original CSV columns, accents and IPA; default language fr-FR and category Leçon 1.
- Seed 21 rows on first login, transactionally and once per account. A CSV conversion command also emits SQL for an existing account.
- Parse CSV/XLSX in the browser, validate again on the server. No local-only fallback when cloud requests fail.
- Keep existing local data untouched; offer an explicit import of legacy browser data. Deployment to a different origin requires exporting data from the old origin first.
- Loading, retry, unauthenticated, denied-access, import errors, and mutation errors are visible states.
- Google/Cloudflare/Vercel account setup and secrets are manual deployment prerequisites. No credentials in source or browser bundles.
